# Research E — local launcher owning cloud sub-jobs

**Date:** 2026-11-17. **Scope:** supported public surfaces only; no private API or credential testing. “VERIFIED” means the cited vendor/source documentation supports the statement; “ASSUMED” is an inference or a supplied prior finding.

## 1. Does the launcher gain a capability?

**Yes for Claude and Copilot; no for the existing Codex Cloud-environment gap.**

* **VERIFIED — Claude Code:** a subscription-authenticated local CLI can now run `claude --cloud "task"` (`--remote` is the deprecated alias), which creates a cloud session for the current repository and returns a session ID/URL; `-p ... --cloud <id>` sends a follow-up and `--teleport` brings its branch/conversation local. It is available on Pro/Max/Ultra/Team and counts against plan limits, with no separate VM charge. For a GitHub remote, the cloud VM clones the current pushed branch; remarkably, if the GitHub App cannot reach it (or there is no remote), the CLI can bundle and upload a committed local repository (under documented size/contents limits). Onboarding creates a default cloud environment, while optional saved environments control setup/network variables. Thus Claude removes **per-repository** registration, but not account onboarding, default-environment creation, GitHub connection/push requirements, policy, or usage limits. [Claude cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web)
* **VERIFIED — Copilot:** `gh agent-task create "…" --repo OWNER/REPO --base BRANCH --follow` is a supported public-preview launcher; `list`/`view --log --follow` return state/logs and the task opens a PR. It works on GitHub repositories reachable by the authenticated user where the cloud agent is enabled (with documented managed-user/disabled exceptions), on paid Copilot plans. There is no separate LazyBridge environment record. [GitHub CLI cloud agent](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-from-cli) [availability](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent)
* **ASSUMED — legacy Codex Cloud:** the supplied prior source audit says the Codex CLI cannot create ChatGPT Codex Cloud environments, `codex cloud exec` requires `--env`, its lookup is server-side, and app-server exposes no cloud task/environment methods; only web/desktop creates a new-repository environment. A local Codex launcher, its subagents, hooks, or MCP merely call the same surfaces and cannot manufacture missing authority. Desktop may provide the human UI, not an automatable supported creation API.
* **VERIFIED — newer OpenAI alternative, not subscription Codex Cloud:** the Agents API offers a managed Codex harness, hosted or self-hosted sandbox, durable sessions, webhooks/streaming, recovery, MCP and subagents; the application supplies files/tools/environment rather than targeting a ChatGPT Codex environment. It is API/container/model metering, not a way to spend a ChatGPT subscription. [Agents API](https://developers.openai.com/api/docs/guides/agents-api/overview) [architecture](https://developers.openai.com/api/docs/guides/agents-api/architecture)
* **VERIFIED — Claude SDK distinction:** Claude Agent SDK sessions run in the caller's process; Managed Agents are the programmatic cloud product and require separately created agent/environment IDs. Neither is the subscription `--cloud` interface. [migration comparison](https://platform.claude.com/docs/en/managed-agents/migration) [managed sessions](https://platform.claude.com/docs/en/managed-agents/sessions)
* **ASSUMED — computer/browser use:** an agent could click a signed-in UI, but this is UI automation, not a supported environment/session API; it adds prompt-injection, MFA, selector drift and accidental-authority risks. Anthropic explicitly warns that browser tools inherit the profile's cookies/account authority. [browser security](https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-sdk)

## 2. Existing supervisor → remote-worker patterns

| Project/pattern | Launch, repository, return/recovery, cost |
|---|---|
| **Claude Cloud / teams & subagents** | **VERIFIED:** repeat `claude --cloud` for isolated parallel VMs; GitHub clone or local bundle; observe/steer in web/CLI, then PR or teleport. Commands/hooks have timeouts and sessions can await answers until environment expiry; parallel jobs consume plan limits proportionally. Local subagents/agent teams are delegation inside their current runtime, not a bypass for cloud setup. [cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web) |
| **Copilot cloud agent** | **VERIFIED:** `gh agent-task create --repo`, poll/follow logs, receive a branch/PR; access is GitHub identity/app/policy rather than environment registration. Failure handling exposed by CLI is status/log follow-up, so LazyBridge must impose deadline/cancel/retry policy. Paid Copilot plan; public-preview surface may change. [CLI docs](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-from-cli) |
| **OpenHands** | **VERIFIED:** open-source SDK/CLI can run agents on local, remote or cloud backends; Cloud adds API and Git-provider integrations. Results/events use its service interfaces; supervisor owns retries/timeouts unless its backend supplies them. Local is free/BYOM; hosted individual is BYOK or model tokens at cost, enterprise custom. [source](https://github.com/OpenHands/OpenHands) [pricing](https://www.openhands.dev/pricing/) |
| **Jules** | **VERIFIED, reject:** CLI/API created remote sessions from a GitHub source, each in its own VM, with pause/resume/logs/branches/PRs; repository first had to be selected through the Jules GitHub App. However Jules is winding down (new work ended 2026-11-11; read-only, then shutdown 2026-12-31), so it is not an option. [CLI](https://jules.google/docs/cli/reference/) [repo/task management](https://jules.google/docs/tasks-repos/) [shutdown](https://jules.google/docs/changelog/) |
| **Devin API; Sweep GitHub app** | **ASSUMED:** representative hosted agent integrations create a vendor session/task against already-authorized repositories and return progress plus PR/diff; the caller must poll/webhook, cap runtime, cancel and deduplicate. They exchange per-seat/usage/API cost and vendor GitHub installation for fewer environment mechanics; neither grants Codex/Claude subscription authority. Treat as candidates requiring a fresh vendor trial, not foundations for the first step.
| **aider + scripts; LangGraph/CrewAI** | **ASSUMED:** these spawn local processes or user-supplied workers, clone/mount repos themselves, and return stdout/state/commits; they provide graph/team control, not hosted repo entitlement. Cost is compute plus model/API usage; the operator implements isolation, cancellation and artifact collection.
| **Temporal / Dagger around any worker** | **VERIFIED/ASSUMED:** infrastructure orchestration, not coding-agent access. Temporal durably records workflow state and supplies activity retry policies/timeouts; Dagger supplies reproducible container execution. Pairing either with the vendor CLI/API improves crash recovery/idempotency but does not register repos. Cost is their control plane/runner compute plus the remote agent. [Temporal retries](https://docs.temporal.io/encyclopedia/retry-policies) [Temporal–LangGraph integration](https://github.com/temporalio/documentation/blob/main/docs/develop/python/integrations/langgraph.mdx) |

**Common risk (ASSUMED):** a natural-language launcher is a confused-deputy with subscription and repo authority. It adds another model call, latency, nondeterminism, prompt-injection surface and duplicate-job/cost risk. A deterministic adapter invoking an allowlisted CLI/API is smaller and more auditable; require repo/branch allowlists, concurrency and cost ceilings, stable idempotency keys, deadlines, cancellation, sanitized logs, and human PR review.

## 3. Benefit for LazyBridge

* **VERIFIED:** Claude now satisfies the hoped-for property most closely: any committed local git repo can be bundled, while an app-authorized GitHub repo is cloned; a Pro/Max subscription can launch it directly with `--cloud`, without a pre-made per-repo environment record. A default cloud environment still exists at account level. [Claude cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web)
* **VERIFIED:** Copilot accepts `--repo OWNER/REPO`; eligibility follows GitHub access, plan and enablement rather than a per-repo execution-environment record. [GitHub CLI cloud agent](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-from-cli)
* **ASSUMED:** Codex Cloud remains blocked exactly where the direct bridge is blocked. Having an LLM type a command adds no capability; only Claude/Copilot's newly supported launchers (or metered Agents/Managed Agents APIs) do. The real benefit is subscription-backed async execution and a local identity boundary, not elimination of platform onboarding or authorization.

## 4. Ranked recommendation (smallest first)

1. **Copilot deterministic adapter.** Probe `gh agent-task create --repo` on one disposable authorized repo, record machine-readable task/PR identity, follow with a hard deadline, and never auto-merge. **Manual:** GitHub/Copilot sign-in, app/policy enablement, repo authorization, review/merge.
2. **Claude deterministic `--cloud` adapter.** On one test repo, launch, capture JSON `{ok, session_id, url}`, poll/steer conservatively, and accept only a pushed branch/PR (or explicit teleport). Test both GitHub clone and non-sensitive bundle. **Manual:** Claude sign-in/plan, initial cloud/default-environment onboarding, GitHub connection where wanted, environment secrets/network configuration, review/merge.
3. **Only if API billing is acceptable: vendor-neutral durable orchestrator + OpenAI Agents API/OpenHands.** Start with one worker contract (`launch/status/cancel/artifact`) and persist idempotent state before adding Temporal. **Manual:** API billing/project keys outside workers, sandbox/repo provisioning and policy. Do **not** build browser automation or a Codex “launcher agent” to evade missing supported APIs.
