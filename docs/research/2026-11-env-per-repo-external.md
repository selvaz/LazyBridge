# Per-repository environments without registration (external survey, 2026-11)

**Method.** `VERIFIED` means the linked documentation/source was read; `ASSUMED` identifies an inference or an item for which no authoritative detail was found. “Registration” means a LazyBridge-style environment record per repository, not granting a GitHub App access once. Prices and limits are intentionally qualitative because they change. The operator's `D:/work/_wt` is unavailable in this cloud clone, so no sibling-repository claim is made.

## The three reusable patterns

1. **Provider GitHub App + repo parameter.** Install once for “all repositories” (or update selected-repo scope), submit `{owner, repo, ref, prompt}`, and receive a PR. Adapter work: OAuth/App connection, task create/poll/cancel, PR normalization, and an installation-scope error. **Subscription:** **VERIFIED yes** for `gh agent-task`; **ASSUMED/plan-dependent** for Codex/Claude/Cursor; Jules API uses its own key.
2. **Ephemeral clone-in-sandbox.** Mint a least-privilege, short-lived GitHub App installation token per task, create a generic image, clone the requested ref, run a headless agent, collect `git diff`, and optionally push a task branch. Adapter work: sandbox lifecycle, credential broker/redaction, image/setup cache, logs/timeouts, patch/PR publisher. **Subscription:** compute is usage-billed; model subscription only if a vendor explicitly supports noninteractive OAuth (Claude Action does; Codex Action does not).
3. **Run in the repository's CI checkout.** Dispatch a reusable GitHub workflow so Actions supplies the exact repo and scoped `GITHUB_TOKEN`; the agent commits or uploads a patch. Adapter work: workflow dispatch/status/artifact handling and a centrally managed reusable workflow. **Subscription:** Claude Action can use Pro/Max OAuth; Copilot organization billing can use `GITHUB_TOKEN` with `copilot-requests: write` ([GitHub workflow auth](https://docs.github.com/en/copilot/how-tos/github-agentic-workflows/creating-github-agentic-workflows)); Codex Action requires API billing.

## Ranked recommendation

1. **Add a Copilot `gh agent-task` engine first.** It is the smallest adapter, directly accepts arbitrary accessible repos, returns a PR, and is the clearest subscription-funded automation. Guard for GitHub-only repos, plan/policy eligibility, credit exhaustion, and the 59-minute cap.
2. **Add a generic ephemeral-sandbox engine with GitHub App token minting.** Use Daytona/E2B/Modal or self-hosted SWE-ReX behind one interface; make patch export the canonical result and PR publishing optional. This is the broadest “any repo” design and removes provider lock-in, but compute and usually model calls are API-billed.
3. **Offer reusable-workflow dispatch for subscription users.** Prefer Claude Action OAuth or organization-billed Copilot. It avoids bridge-side repo environments and private-code custody, at the price of one workflow enablement (ideally organization-wide) and Actions latency.

Do **not** model Amp-style Projects/Jules Sources as the replacement: they merely move per-repo registration to another service. Treat Codex/Claude signed-in CLI tokens inside third-party sandboxes as an experimental opt-in until vendor terms and unattended refresh behavior are explicitly documented.
