# Documentation audit — October 2026

Audited on 2026-10-11 against source commit `e475be8` in the
`LazyBridge-docs` worktree, branch `docs/engines-collaboration`.
Package version: **1.8.0**, with subsequent Codex discovery/transport fixes
already present in this source baseline. This audit is deliberately absent
from navigation and the configured LLM corpus.

The scope was all 111 instructional Markdown pages present before this refresh
(116 pages including five marketing drafts), plus README, root CHANGELOG,
MkDocs navigation/version metadata and the linked `lazybridge/llms.json`
code-generation contract. Marketing drafts were excluded from the API audit.
Historical migration material was checked as history, rather than rewritten
as current usage.

The starting editorial evidence was the requested website strengths analysis
`lazybridgewebsite-refresh/_drafts/strengths-2026-10.md` and rebuilt
`lazybridgewebsite-refresh/docs/index.md`. LazyTools integration behavior was
checked against the read-only `LazyTools-docs` documentation. All edits and
test/build artifacts belong to this worktree; the shared editable LazyBridge
checkout was not modified.

## Evidence and method

Source contracts were checked in:

- `lazybridge/agent.py`, `_verify.py`, `engines/base.py`, `testing.py`:
  construction, invocation, identity, verification and mock behavior.
- `engines/claude_code/{engine,protocol,sdk_client,mcp_adapter,usage}.py`:
  native policy, SDK options, attachments, persistence, streams and usage.
- `engines/codex/{engine,app_server,dynamic_tools,usage}.py`:
  JSON-RPC lifecycle, strict schemas, dynamic tools, resume, usage and errors.
- `engines/{coding,sessions}.py`: approval profiles, grants, SessionRegistry,
  path/key normalization and lock boundaries.
- `engine.py`, `sentinels.py`, `ext/hil/`, `exporters.py`, `session.py`,
  `store/`, `ext/{approval,delegation,knowledge}/`, `control_plane/`:
  Plan execution, state, observability and post-1.1 orchestration.
- `pyproject.toml`, `CHANGELOG.md`, engine/approval/delegation unit tests,
  existing documentation example/path tests and LazyTools code bridge,
  code support, MCP and projects documentation.

An AST inventory checked imports, constructor keywords and positional arity in
Python fences against the installed source signatures. Non-LLM Agent names and
legacy/future-phase language were checked separately. Intentional API signature
specifications, illustrative checkpoint records and migration “before” examples
were distinguished from executable examples. Changed Python examples are now
extracted from the Markdown and executed by
`tests/unit/test_docs_refresh_snippets.py`, using a checked-in selection manifest.
Only transport/model calls are faked; Agent, verification, Plan, tools, policy
objects, registries and persistence execute their real code paths.

## Historical material retained intentionally

- Migration guides and dated changelog sections retain old LazyAgent,
  LazyTool, wrap_tool, configuration objects, MCP shims and unnamed Plan
  examples where explicitly showing an older release. Their removal history
  is evidence, not current API advice.
- “Signature” fences and illustrative checkpoint/event dictionaries are API
  specifications, not standalone programs. They were not rewritten into fake
  executable examples. Changed executable blocks are tested from their actual
  Markdown; fragment setup supplies names already established in guide prose.
- Provider catalogue/history data and the withdrawn April 2026 release
  numbered 1.0.0 are not overwritten with a fictional clean version history.
- Quota telemetry, live CLI interoperability and subscription consumption are
  runtime-dependent. No live model calls, billing experiment or quota routing
  benchmark was performed for this refresh.
